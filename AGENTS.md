# Working on Aegis (for coding agents)

- **Source of truth:** `aegis.js` — one ES module, plain JavaScript, no build, no dependencies, no `eval`/`new Function`, no `innerHTML` with data. Sections are numbered `// N. NAME`; keep new code in the section it belongs to.
- **Types:** `aegis.d.ts` is hand-written. Every new export gets a declaration and a one-line JSDoc there.
- **Tests:** `test/test.html` (browser, about 1,077 assertions in ~50 sections) and `test/test-core.mjs` (`npm test`, the reactive graph on Node, 42 tests plus a fuzzer). Add a test for every behaviour change; edge cases over happy paths. `npm run test:browsers` runs the browser suite in headless Chrome and Firefox, `npm run test:webkit` in Playwright WebKit; the runners serve the repository root.
- **Distribution:** `npm run build` (esbuild dev dependency) produces `aegis.min.js`, `aegis.core.js` and `aegis.core.min.js`; they are committed and never edited by hand. Users never build. Releases are git tags `vX.Y.Z`; the site serves the tagged files under `https://aegisjs.com/X.Y.Z/` with integrity hashes.
- **Dev warnings:** use `_warn('Exxx', !globalThis.AEGIS_PROD && { what, why, fix })` with a new code listed in `ERRORS.md`. Never `console.warn` directly.
- **Docs:** README is the pitch, the rules, the ten names and the install; the long chapters are `docs/*.md` (the site builds its pages from them). A feature change updates its chapter, not the README.
- **Principles that decide API questions:** server-first (HTML from the server, JS hydrates), zero-build, ownership (every effect, listener, timer and resource is owned by a scope and dies with it; outside a scope it is E001 — a reported leak, not magic; `defaults.orphanEffects` decides the production behaviour), CSP-native, coexist with jQuery/Bootstrap (never touch classes or listeners you did not add, never delegate on `document` by default), AI-native (one obvious way, see `llms.txt`).
- **Conventions:** internal helpers start with `_`; signals expose `.value`/`.peek()`; disposers are functions; options are the last object argument; new DOM helpers accept `Reactive<T>` (value | signal | getter).
- **Do not:** add a build step for users, add runtime dependencies, add global mutable registries (use `provide/inject`), parse HTML from data, or introduce a second way to do something that already has one.
